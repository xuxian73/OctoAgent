# 审计与安全边界

`audit_events` 是独立的安全审计表。业务服务公共入口和 MCP 工具、资源入口记录主体、租户、服务端实际通过的 scope、对象、结果和 request_id。权限签发与撤销也写入此表。业务变更与成功审计共用事务；审计写入失败会回滚变更。普通应用没有审计修改、删除或跨租户查询接口；SQLite 触发器同时阻止 UPDATE、DELETE 和替换已有序号。数据库所有者仍可以删除触发器或修改文件，本实现不声称外部不可篡改存储或合规认证。

`object_type` 和 `object_id` 由业务入口显式指定，与授权 scope 分开：创建记录生成的需求、报价或附件 ID，后续操作记录对应对象 ID；凭据记录 SHA-256 摘要标识及 `target_subject`（内部用户或 Agent ID），不记录可登录的 token。幂等重放保留相同业务对象关联。拒绝的调用不复制未验证的输入 ID，使用 `none`；历史审计行通过新增列默认值保留，不改写已有事件。

审计摘要只采用固定服务端文案，不复制任务、代码、评论、附件名称、工具结果、凭据或异常文本。错误响应采用固定文案和错误码；`safeDiagnostic` 对任意异常内容整体脱敏，包含无法根据格式识别的私人信息。业务数据和原有业务时间线仍受原有授权保护，不应作为日志导出。不要在诊断日志中直接序列化请求、响应或异常。

HTTP 创建草稿、报价、澄清、补充说明、回答和附件登记支持 `Idempotency-Key`。同一主体、同一键、相同方法及参数重放只返回原结果；不同参数返回 409。重放重新检查身份、当前 scope 和原角色，不能用缓存绕过撤销。键与参数仅以摘要形式索引，结果属于受保护的业务数据。状态命令沿用既有 requestKey、版本和人工确认规则；MCP 沿用 request_id 幂等机制。调用方重试时应保留原键；不同业务操作应使用新键。

`CallbackVerifier` 是离线适配器边界，不开放生产回调端点。HMAC-SHA256 签名消息为 JSON 数组 `[source, timestamp, nonce, sha256(base64(body))]`；时间戳单位为毫秒，时间窗正负五分钟。签名使用恒定时间比较，nonce 在数据库中唯一且不会因进程重启失效。适配器必须在应用回调效果之前校验；校验失败不应泄漏原始请求。生产密钥配置和真实回调集成不在本 issue 范围。

附件目前仅登记元数据，保持原有“不上传文件内容”的 UI。其类型、扩展名、大小和扫描策略由服务端校验；元数据通过 fake scanner 不代表真实文件完成病毒扫描。离线工作区制品会将实际字节传给可替换 `Scanner`，检查类型、大小和基本文件特征，扫描感染、不可用或抛错均拒绝保存。FakeScanner 仅识别离线测试标记，不是防病毒产品。未来真实文件存储接入必须提供真实内容并替换扫描器，不能把元数据扫描结果当作文件放行证明。

UI 和 MCP 明示任务、仓库文件、评论和制品为不可信数据。提示词中的业务上下文与授权指令分离；授权始终由服务端身份、scope、角色、版本和人工确认控制。内容中的“忽略指令”“扩大权限”不能改变这些规则。
