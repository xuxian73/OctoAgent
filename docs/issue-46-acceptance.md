# #46 ZIP MVP 验收

## 独立启动

先安装 Node 22.22.1、npm 10 和 lockfile 依赖（离线环境预备缓存后使用 `npm ci --offline --no-audit --no-fund`）。仓库根目录执行：

```sh
npm run build
node scripts/zip-acceptance.mjs
```

脚本不加载 `.env`，每次创建独立临时目录、空 SQLite 数据库和两版正常 ZIP 样本，应用迁移但不预建账户、不注入权限。真实文件字节位于该数据库的 `private_files.bytes`，无共享存储目录。使用回环地址和 `PORT=0` 由系统原子分配空闲端口；打开输出的 URL。Ctrl+C 停止；数据保留在输出目录供复核。不要将数据库作为公开证据提交，其中含账号及会话。启动受限制报 EPERM 时，应在允许本地监听的开发环境重跑，不能宣称网页通过。

默认使用真实 ClamAV。预先安装可信扫描器与病毒库，设置 `CLAMAV_EXECUTABLE` 为绝对路径（默认 `/usr/bin/clamscan`），`CLAMAV_TIMEOUT_MS` 默认 30000、最多 60000。程序或病毒库不可用时上传不能放行；不提供切换测试扫描器的部署开关。先单独运行 `npm run scan:integration`，记录 clean、clean-zip、EICAR、EICAR ZIP 四项实际结果；样本在独立临时目录生成并清理，不运行样本内容。

ZIP 输入默认最多 10 MiB、每资源版本 20 个文件；`FILE_MAX_BYTES` 可降低上限，`FILE_MAX_COUNT` 调整数量，`FILE_EXTENSIONS` 必须包含 `.zip` 才能交付。详情及归档结构限制见 [ZIP 交付](zip-delivery.md)、[私有存储](private-files.md)。乙方资料的名称/能力/任务类型/简介分别最多 80/500/500/1000 UTF-16 单元，入驻 JSON 总上限 16 KiB，涵盖中文及 JSON 转义；登录注册仍为 4 KiB。

## 正式网页操作与证据

必须由本聊天的浏览器工具操作正式网页，不能通过业务 API、CLI 创建账号或改库补权限。使用两个独立浏览器配置会话，或在同一浏览器严格退出后换账号；注意同浏览器标签共享 Cookie。全部为本地合成数据，无真实支付。

1. 甲方打开 `/register` 注册全新账号，经 `/login` 正常登录，在身份页创建组织与项目。记录注册成功、角色与项目截图，勿记录密码。
2. 填写需求，预览摘要并人工确认发布。乙方另行注册、登录，填写中文乙方资料，创建自己的责任组织。进入“公开市场”，发现甲方任务、填写报价、预览并确认提交。
3. 甲方从项目直达链接进入需求与报价，比较并选标。双方从“我的报价/订单”进入合同，各自核对同一版本并确认。不得替另一方确认。
4. 甲方从合同进入交付工作区，通过页面分别授予乙方本人文件上传和提交权限（最长 15 分钟，过期须重新授权）。乙方选择里程碑与第一版 ZIP，等待真实扫描，填写说明、运行方法、已知问题，再提交。
5. 甲方下载第一版，保存为 `download-v1.zip`；核对源包和下载包字节及 SHA-256、页面文件大小、扫描器及扫描 checksum。填写原因并人工确认要求修改。
6. 乙方上传内容不同的第二版 ZIP，可使用同名文件，重新填写说明并提交。甲方下载为 `download-v2.zip`，核对第二版并重新下载第一版确认历史未覆盖。旧页面不能验收新版本。
7. 甲方明确验收当前交付，全部里程碑通过后完成合同。保存历史版本与完成状态截图。乙方增加甲方项目形成双角色后，仍可通过“公开市场”发现其他组织需求；身份页项目链接应直接可用。
8. 单独记录空文件、非 ZIP、损坏、超限、扫描不可用/失败、未中标者、撤权、旧版本/幂等重放及争议冻结结果。无法在网页触发的 API/MCP 回归需标注为自动测试，不能冒充网页步骤。

证据保存在启动输出目录下的 `evidence/`：`steps.md`（每步通过/失败/阻塞）、截图 `01-register.png` 至 `08-completed.png`、下载两版 ZIP、`checksums.txt`、`scan.log`。使用 `shasum -a 256` 记录四份文件，用 `cmp` 分别逐字节比较；记录 `git rev-parse HEAD` 与未提交工作区差异，提交后重跑则记录最终 SHA。截图避开密码、Cookie、令牌和个人数据。公开仓库仅提交脱敏报告与合成证据。
