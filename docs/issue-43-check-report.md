# Issue #43 检查报告

实现了显式 GitHub 连接配置和甲方确认/撤销入口、独立 read/write/create_pr 权限、GitHub REST blob/tree/commit/ref 同步、PR 创建/恢复、远端检查读取和本地/远端 SHA 映射。merge/deploy 无执行入口。无需 GitHub 的真实本地 Git 继续可用；远端检查单独存储，不转成隔离检查通过证据。

最终使用默认环境运行 `./scripts/check.sh` 成功：格式、TypeScript、构建、数据库检查 4/4、完整测试 164/164，零失败、零跳过。`git diff --check` 通过。没有提交、push、gh 或生产联调。

`tests/github.test.ts` 八项集成测试覆盖真实 Git 对象、HTTP 协议、权限和身份错误、响应丢失、并发/租约恢复、数据库部分失败、浏览器事件入口及部署配置权限。测试认证值运行时随机生成，不记录真实秘密。本沙箱 TCP 和 Unix socket 监听均返回 EPERM，因此本地 HTTP stub 使用内存双工字节流，由 Node HTTP 客户端与服务端执行真实 HTTP 序列化/解析；不是 FakeGitHubProvider，也不是实际 GitHub 联调。

本轮补齐新增迁移对应的 schema 快照和升级 fixture。后续默认环境完整检查复现了 ClamAV 正常子进程用例的 1 秒超时，而单独运行可通过。正常进程用例现在统一允许 10 秒，以容纳并行负载及新建可执行文件的启动耗时；专门验证超时拒绝的 20 毫秒用例及所有断言保持不变。未修改生产逻辑或检查脚本，也无需覆盖 `TMPDIR`。

Reviewer 请重点检查：

- 服务端私密配置绑定合同、甲方、仓库数字身份、凭据引用、scope 上限及有效期；浏览器不接收凭据。
- Blocker 1：采用禁止删除的保守修复。同步前读取固定 base SHA 的完整递归树，列出缺失路径并在任何远端写入前拒绝；不开放人工确认删除入口，通用写权限不可绕过。递归树截断、基线变化、重复调用及 PR 创建都覆盖拒绝测试。
- Blocker 2：新增持久化一次性连接计划，绑定合同版本、责任主体、配置摘要、scope、TTL 和绝对到期时间。页面先展示计划，再重新勾选确认；成功连接、降权和撤销原子作废所有旧计划。重复请求不延长有效期，旧请求、其他页面延迟请求、缺少标识、配置/期限/合同变化和过期计划均拒绝。新增迁移及 schema 一致性检查。
- 不可变计划与预期 Git 对象 hash、分支/PR 回读、SQLite 租约及失败恢复；证据与不可变合同事件、审计在同一事务发布。
- 远端证据显式区分 localSha/remoteSha 与读取时间；空检查、错误身份、过期或撤销连接不能形成新成功证据。
